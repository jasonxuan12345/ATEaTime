# Release 计算内存与速度优化

实现日期：2026-10-27。

本次处理 CPK、CGM、Site Diff、Outlier 的样本分组、读取、结果引用和页面响应。计算继续使用内存中的计算视图；统计使用全部符合各模块规则的记录。

## 已实现

### 原生计算视图的紧凑索引

`release_event_index.py` 使用 `CalculationStore.definition_codes` 和共享定义建立测项身份，不再逐颗芯片解码相同的八个身份字段。导入时明确标记 `last_per_test`，只有已经处理过重复执行的输入才跳过再次去重；其他输入保留兼容处理。

两遍构建分组：先计数，再分配并填充连续的记录编号数组。构建使用最多约 13 万条记录的排序缓冲，不对全部事件创建 Python 对象或全量排序副本。分组保留芯片与测项执行顺序，规格、条件及结果编号仍参与身份区分。

记录编号按范围使用 uint32 或 uint64。目录只保存每个存储块与芯片记录的区间；结果引用从编号取得原始 Part Index、测试序号及 Site。原始测试序号不降精度，测量值按 float64 计算。

`IndexedReferences` 共享分组编号数组，并用位图记录有效样本。CGM 与 Site Diff 的相同有效样本集合共享引用对象。读取旧 `sample_refs` 接口时仍返回相同的字典序列；JSON 导出按记录展开。

### 分批准备样本

`prepared_groups()` 根据工作区预算分批读取测项，按存储块集中读取，计算完一批再释放其数组。取消保留所有测项 `events.prepared` 的做法。内部计算使用 NumPy 数组，减少 Python 浮点列表及列表与数组之间的转换。

相同选样的 CGM 和 Site Diff 复用各 Site 的 n、Mean、Std。两者的分类与样本充分性判定各自执行。Site Diff 内部 CGM 使用 `_metrics_only=True`，不建立完整样本引用。CGM PDF 的 MR 诊断保留原始测试顺序。

Outlier 对长度相同的参考组批量调用精确线性分位数计算。各组的样本独立，不合并不同文件、测项及条件、Lot、Wafer、Head、Site。样本量不足、零四分位间距、非有限结果和严格大于阈值的行为保持原有规则。

### 有容量限制的缓存与结果清理

| 配置 | 默认值 | 范围 |
|---|---:|---|
| `DEEPYIELD_RELEASE_SCRATCH_MB` | 128 MiB | 分批读取的工作区规划预算 |
| `DEEPYIELD_RELEASE_INDEX_CACHE_MB` | 512 MiB | 全进程原生分组索引缓存，包含元数据开销估算 |
| `DEEPYIELD_RELEASE_VALIDITY_CACHE_MB` | 64 MiB | 全进程事件有效性及必要数值转换缓存 |
| `DEEPYIELD_RELEASE_CHART_CACHE_MB` | 64 MiB | 全进程图表样本缓存，保守估算字节数 |
| `DEEPYIELD_RELEASE_RETAINED_INDEX_MB` | 768 MiB | 已保存报告持有的样本索引与位图预算 |

缓存相同来源、相同选片、相同测项的原生分组，供后续计算使用。改变选择范围会建立新分组，不会错误使用其他范围的结果。超过缓存预算的索引仍可用于当前计算，但不进入缓存。

报告预算按共享数组实际所有者去重；超过预算时依次释放较早的结果，至少保留当前结果。它与索引缓存的预算分别管理，二者可能共享相同缓冲，不能直接相加当作实际占用。单个当前结果大于报告预算时仍保留该结果。

有效性缓存用弱引用关联原始存储对象，避免缓存成为已删除源数据的额外所有者。删除或过期的数据集会清理对应缓存和依赖它的报告；已经开始读取的请求可持有自己的临时引用直至结束。大型分析请求串行执行，等待时可取消，避免同时分配多套工作区。

工作区预算用于批次规划，不是操作系统级硬上限。单个超大测项仍进行完整精确计算，可能超过该预算。所有预算均不包含原始数据、全部结果对象、Python/NumPy 内存分配器及导出器的总占用。

### 页面精简响应与按需诊断

页面请求携带 `X-Release-View: summary-v1`：

- 常规检查先返回全部列表必需指标及简短诊断，不重复返回每个单元格的完整来源与知识依据。
- Outlier 命中记录以参考组位置、测试序号、实测值、偏离度和方向传输，省去重复的测项名称、规格和参考统计；前端解码为原有显示结构。
- 展开“本次依据与项目经验来源”才读取完整诊断。读取失败会显示错误，重新展开可重试。
- 全局轻量列表和稀疏命中仍完整提供，以保留现有全局搜索、排序、计数及矩阵。没有使用当前页替代全量数据。
- 提供候选记录与命中明细分页接口，每页最多 200 条。当前界面的全局候选表和矩阵仍基于轻量完整集合进行分页，不需要为每次翻页重新计算。
- Excel/PDF 使用后端完整报告。显式 JSON 导出先读取完整 Outlier 报告，确保来源和诊断依据齐全。

不携带此请求头的旧客户端继续获得原来的完整响应结构。

新增读取接口：

```text
GET /datasets/{dataset_id}/runs/{run_id}/items/{key}/diagnosis/{module}
GET /datasets/{dataset_id}/outliers/{report_id}/baselines/{baseline_id}/diagnosis
GET /datasets/{dataset_id}/outliers/{report_id}/candidates?offset=0&limit=40&group_id=...
GET /datasets/{dataset_id}/outliers/{report_id}/candidates/{part_index}/hits?offset=0&limit=40
GET /datasets/{dataset_id}/outliers/{report_id}/report
```

上述接口均使用 `/api/release-check` 前缀。数据集或结果过期后返回 404，分页边界无效返回 422。

## 性能验证

基准脚本：`examples/benchmark_release_compute.py`。数据在内存中生成，不读取客户 STDF。固定随机种子，3289 条芯片记录 × 3713 测项 = 12,212,057 条事件，16 个 Site、每个存储块 32 条芯片记录。在同一宿主环境的一条命令中，依次启动新进程运行修改前与最终实现。

| 项目 | 修改前 | 修改后 |
|---|---:|---:|
| CPK + CGM + Site Diff | 114.25 s | 53.75 s |
| Outlier | 181.54 s | 40.00 s |
| 两段计算合计 | 295.79 s | 93.75 s |
| 进程历史最高工作集 | 1447.03 MiB | 712.46 MiB |

最终连续对照的合计时间减少约 68%，峰值减少约 51%。初轮对照为 70.38 s → 26.13 s、1414.41 MiB → 711.36 MiB；另一次未配对复测为 105.82 s，不能据此计算加速比。各轮原始结果均保留在 JSON 中。

这是相同测量数据的合成对照，绝对运行时间明显受机器负载影响。该合成数据只命中 1 条异常记录，不能代表高异常命中率场景的结果对象占用。模块状态计数和 Outlier 命中计数一致；额外的逐值测试覆盖正常值、重复执行、空值、规格变化及无效记录。基准不包含导入、诊断知识库生成、HTTP 返回、浏览器绘图或 PDF 导出，也不代表客户四文件量产场景的实测成绩。

复测命令，在项目根目录执行：

```powershell
$env:PYTHONPATH='.'
python examples/benchmark_release_compute.py
```

`--parts`、`--tests`、`--sites`、`--batch-parts`、`--conditions` 可调整规模。不要让前后两次基准与其他重负载任务同时运行。对照原始记录见 `docs/benchmarks/release-compute-20261027.json`。

日志继续保留 Windows `peak_rss_mb` 历史峰值，新增 `memory_start_mb` 与本次操作期间每 200 ms 采样的 `sampled_peak_rss_mb`。后者可能漏掉极短暂的峰值，而且覆盖的是整个后端进程，不能将并发图表的内存单独归因给分析任务。

工作区事件数量/输出字节、索引字节、缓存字节、等待、分批准备、分组和统计耗时均写入现有 `release_perf`。下一步用同一批真实量产文件验证首次计算、重复计算、改变选样、取消、删除来源和连续重算。

## 回归验证

计算与报告回归覆盖 485 项原有测试及 13 项新增精确性、缓存、取消和释放测试；全部 Release API 共 135 项通过。原生合成 STDF 的跨文件分析及四种 Site Diff/Outlier 报告下载额外通过集成验证。前端 156 项测试及生产构建通过，六种宽度的中英文页面检查共 156 个状态通过。

前端 ECharts 首次导入在本机并行测试中偶有 5 秒超时；最终使用单工作进程、15 秒测试超时完成全量测试，未修改产品计算逻辑或测试断言。
