# 导入与 Parquet 导出

默认导入只建立计算数据，不写 Parquet。页面分析、图表和报告继续使用内存中的计算数据。

## 默认导入

1. 上传的 STDF 原始字节保存到会话临时目录；压缩文件保持压缩形式。
2. C++ 解析器通过 `--release-calculation-ipc` 输出分批计算数据，格式版本为 `deepyield-release-calculation-v1`。
3. 输出包含芯片信息、测项身份、单位、有效上下限、结果、测试标志、有效性与记录序号。不输出重复测量宽表列、告警文本和原始可选字段。
4. 每个 PRR 内，同一测项列保留记录序号最大的执行；相同序号保留先出现的记录，测项顺序保持首次出现顺序。最后一次结果无效时不会回退到之前的有效结果。不同 PRR 不合并，失败芯片也不会在导入时删除。
5. Python 分批构建内存计算视图。IPC 仍使用临时文件交换；解析结束后的临时 IPC 会关闭并清理。

解析器仍先读完 STDF，以处理末尾 TSR 和后续补充的测项名称。此次没有改为解析与读取同时进行，也没有承诺固定的导入提速比例。

## 保存完整 Parquet

页面“原始数据 → 保存 Parquet”请求 `/datasets/{id}/parquet?job_id=...`，从保留的 STDF 重新调用全量解析模式 `--release-ipc`。

- 文件仍为 `wide_all` 格式，包含全部执行记录和原有字段；计算格式不会冒充全量格式。
- 首次生成支持状态查询和取消。转换成功后才发布最终文件；失败或取消会清理未完成的文件，并保留 STDF 供重试。
- 同一数据集同时请求时只执行一次转换。成功后再次下载复用已生成的文件。
- 不修改内存计算数据、选样或已保存的检查结果。
- 删除或过期的会话释放临时目录。正在进行的转换或下载会保持目录有效，直到使用结束。

命令行 `convert_stdf_to_wide_all(source, destination)` 仍显式生成全量文件。Python `import_release_stdf(source)` 现在只返回计算 frame 和 metadata，不再接受输出路径。更新代码后需要重新构建 C++ 解析器和前端。

## 验证入口

- `test_release_native.py`：计算输出、压缩输入、无 Parquet 写入、重复执行与完整报告结果对照。
- `test_release_lazy_parquet.py`：保留原文件、延迟生成、完整执行历史、重复请求、取消/失败重试与目录清理。
- `test_release_compact.py`：分批计算、选样及图表/报告一致性。
- C++ `test_release_arrow`：分批输出、最后一次执行和后补测项名称。
- 前端 `ReleaseCheckPage.test.tsx`：按需生成期间禁用重复操作，完成下载及失败重试。
